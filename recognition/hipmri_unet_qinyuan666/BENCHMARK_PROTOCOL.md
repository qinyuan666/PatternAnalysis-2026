# 整病例推理测速方案

沿用 [测试方案](TEST_PROTOCOL.md) 的两个冻结权重、同一清单和测试病例，不训练或调参。
测试集有 3 个 Case，分别含 420、60、60 张切片。同一 Case 的全部周次合并计时，
因此这里的“整病例”不是单次 60 张扫描，也不是三维体积重建。

## 两种计时范围

1. **图像到预测的流程时间**：包括 NIfTI 图像读取、归一化、缩放补边、组 batch、
   GPU 输入传输、模型前向、argmax 和预测掩码返回 CPU；还包含非有限值检查与同步开销。
   为复用已核验的预处理函数，补边函数内部会处理一个全零占位 mask；不读取真实标注。
   不含模型初始化/权重加载、预热、末尾合并/哈希或写文件。
2. **纯前向时间**：每个 batch 输入已在 GPU 后开始计时，前后同步 CUDA，
   再累加完整病例的所有 batch。排除读取、预处理、输入/输出传输和 argmax。

流程时间中嵌套了纯前向计时，因此包含逐 batch 同步开销，不能称为充分优化的部署吞吐率。
不直接用“单张速度 × 切片数”推算病例时间，而是实际遍历所有切片。

## 固定测量设置

- CUDA float32，batch size 4，CPU threads 4；模型 eval、禁用梯度。
- 每个病例/模型测量 3 次，每次先做 5 次前向预热；完整保留每次值及中位数、最小值、最大值。
- 按病例和重复轮次交替两模型顺序，缓解顺序偏差；同时只有被测模型放在 GPU。
- 不清除操作系统文件缓存，因此是模型已预热、文件缓存可能已命中的测量，不能当冷启动读盘时间。
- 计时外校验每个病例的预测数量与哈希，报告重复间预测是否一致。
- 核验权重和清单哈希；公开记录只保留测试 Case 别名，不保存源病例编号。

仅测量本机一个会话，温度、功耗和其他进程未严格控制。复现时保持接电，避免游戏等 GPU 竞争任务。
结果描述这次硬件和流程，不推断所有设备的速度倍率。训练显存与单张耗时仍见原正式训练报告，
本次不把同时驻留模型或框架缓存的占用误当作单模型训练峰值。

## 运行

在项目目录和项目 Python 环境执行；输出目录必须不存在。预计是几分钟级评估，不会重新训练。

```bash
python benchmark_cases.py --checkpoints runs/real_unet_20ep_s3710/best.pt runs/real_improved_unet_20ep_s3710/best.pt --manifest private_data/manifests/course_v1.csv --output runs/test_case_benchmark --device cuda --split test --batch-size 4 --repeats 3 --warmup 5
```

完整输出在 `runs/test_case_benchmark/summary.json`，复现时更换新目录。
测试覆盖图像预处理与训练数据加载的一致性、缺少标注时仍能测速、末尾不足 batch 的切片、
病例分组、重复预测与交替顺序、权重未修改以及清单/输出目录保护。
