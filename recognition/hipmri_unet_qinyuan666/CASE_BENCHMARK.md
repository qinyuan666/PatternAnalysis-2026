已使用两个冻结的测试权重，在 RTX 4070 Laptop GPU 上对三个测试 Case 各重复测量 3 次。
**用户随后确认：测速期间正在运行游戏或其他 GPU 任务。本组记录受竞争负载干扰，不能用作公平的模型速度比较。**
保留全部原始数值作为受干扰运行记录；需要在其他 GPU 任务关闭后，使用新目录重测。
方案与范围见 [测速方案](BENCHMARK_PROTOCOL.md)，完整精度及各次记录见

## 图像到预测的流程耗时

单位秒，报告三次中位数，括号为最小–最大值。包含图像读取、预处理、输入传输、前向、
argmax、预测返回 CPU、数值检查及逐 batch 同步；不含模型加载/预热、末尾合并/哈希或写文件。

| 测试病例 | 切片数 | U-Net（秒） | Improved U-Net（秒） |
|---|---:|---:|---:|
| Case 01 | 420 | 5.173（4.687–5.497） | 6.452（6.449–6.785） |
| Case 02 | 60 | 0.698（0.695–0.734） | 1.004（0.984–1.008） |
| Case 03 | 60 | 0.666（0.643–0.803） | 0.886（0.845–0.933） |

每个 Case 汇总其全部周次，Case 01 包含 7 个周次，另外两例各一个周次；
不应把 420 张切片的整病例时间解释为单次扫描时间。
病例别名与测试评分报告一致，与验证集同名别名不是同一病例。

## 纯模型前向耗时

每批输入已传入 GPU 后开始计时，CUDA 前后同步，然后累加病例的全部 batch。
它是上述流程中的一部分，排除读取、预处理、输入/输出传输及 argmax。

| 测试病例 | U-Net（秒） | Improved U-Net（秒） |
|---|---:|---:|
| Case 01 | 1.933（1.796–2.467） | 3.621（3.606–3.691） |
| Case 02 | 0.250（0.231–0.299） | 0.542（0.510–0.599） |
| Case 03 | 0.267（0.224–0.316） | 0.465（0.423–0.529） |

流程和前向分别取中位数，不能将两个中位数之差视作独立测得的预处理耗时。
此前训练报告的单张模型计时采用 batch 1；本次 batch 4，不能直接按单张数字乘切片数比较。

## 条件、核验与局限

- PyTorch 2.5.1 / CUDA 11.8、float32、batch size 4、CPU threads 4。
- 每次测量前 5 次前向预热；交替模型执行顺序，测速程序自身同一时刻仅将被测模型放在 GPU，但还有用户确认的外部 GPU 任务。
- 540 张真实测试图像全部遍历，重复中不加载真实标注；复用预处理函数时包含占位 mask 的计算开销。
- 所有病例/模型的三次预测哈希一致；切片计数、权重/清单/源码哈希及中位数、范围已核验。
- 四项针对性测试验证图像预处理与数据加载器一致、标签缺失时仍可推理、末尾不足 batch、分组、顺序和输出保护。

操作系统文件缓存没有清除，因此不是冷启动磁盘性能。逐 batch 同步与数值检查使这成为
带检查的可复现流程计时，不是充分优化的部署吞吐率。温度、功耗未严格控制，其他 GPU 任务已确认存在。
一次运行中的显存占用包含驱动、桌面和可能的其他进程，不能用其代替训练报告的单模型峰值。

结合 [测试分数](TEST_RESULTS.md)，Improved U-Net 的像素汇总 Dice 略高，而前列腺病例均值近似持平。
原报告从本次计时推断基线速度优势的结论撤回，等待无竞争负载时的复测。
该反馈针对测速条件，不改变已有冻结权重或测试 Dice/IoU 记录；无需因此重新训练。
最终边界表现仍需分析，不能据本次数据宣称临床实时性或更准确的轮廓。
